UNNG Mobile App UI/UX Design Specification
1. Source Requirements Summary
This UI/UX specification is based on the UNNG SRS and user flows provided by the client. The platform includes a
cross-platform mobile app for iOS and Android, plus a web admin dashboard. The core product is a membership and
community platform with events, donations, subscriptions, organizations, forums, user profiles, transactions,
notifications, reporting, and admin management.
Area UX Interpretation
Primary user value Join and participate in UNNG community, discover events and
organizations, contribute financially, and interact in forums.
Primary admin value Manage users, events, organizations, subscriptions, transactions,
forums, reporting, and configuration from one efficient dashboard.
Business model UX impact Payment and membership status must be highly transparent
because forum posting and paid access depend on
payment/subscription state.
Phase approach Phase 1 must include core membership, events, payments,
organizations, forums, profile, transactions, notifications, admin
management, and basic KPIs. Phase 2 can add QR check-in, points,
courses, advanced analytics, refunds, push notifications, and
organization dashboards.
2. Design Principles and Best-Practice Decisions
These decisions keep workflows smooth, modern, and low-friction while respecting iOS, Android, web, and
accessibility expectations.
Principle Decision
Clarity before decoration Every screen must make the next best action obvious. Use one
primary CTA per state and keep secondary actions visually quieter.
Low-click completion Common actions should complete in 1-3 taps/clicks after the user
reaches the relevant screen: register event, donate, subscribe,
comment, search, filter, and view transaction.
Progressive disclosure Show essential information first; reveal advanced filters, details,
audit data, and moderation tools only when needed.
Platform-native behavior Use iOS conventions on iPhone, Material Design
navigation/components on Android, and responsive
data-table/dashboard patterns on web.
Accessible by default Meet WCAG 2.2 AA intent: sufficient contrast, clear focus states,
large touch targets, keyboard navigability, dynamic type support,
and readable labels.
Error prevention and recovery Validate forms inline, preserve entered data, confirm destructive
actions, and provide retry paths for payment, upload, and network
failures.
Trust in payments Always show amount, plan/event name, recurrence, payment
processor, terms, and confirmation before launching Revolut Pay.
Community safety Forum posting must make rules visible, guide users toward
respectful content, and support moderation states without
surprising users.

 Personality: trustworthy, warm, modern, community-focused, and action-oriented.
 Layout style: clean surfaces, rounded cards, generous spacing, readable typography, clear hierarchy.

4. Accessibility and Inclusive Design Requirements
Requirement Mobile App Web Dashboard
Contrast Text and controls must meet WCAG AA
contrast; never rely on color alone for
status.
Same; charts require labels/tooltips and
non-color differentiation.
Touch/click target Primary touch targets 44-48 pt/dp
minimum; avoid tightly packed icon-only
controls.
Clickable controls at least 24 CSS px
minimum with clear spacing; main
controls 32-40 px.
Screen reader All icons, images with meaning, buttons,
tabs, chips, and form errors need accessible
labels.
Tables need column headers, form labels,
focus order, and keyboard-accessible
menus.
Dynamic type/responsive text Layouts must survive larger text sizes
without clipping.
Browser zoom to 200% should remain
usable.
Focus visibility Native focus for mobile assistive tech;
visible focus for web keyboard navigation.
2 px or stronger focus ring, 3:1 contrast
against nearby colors.
Error handling Inline error below field, summary for long
forms, do not clear data.
Same; scroll/focus first error after submit.
5. Copywriting and Microcopy Rules
Situation Recommended Copy Pattern Avoid
Payment review “You are about to pay $50 for Super Hero
Subscription. Your membership becomes
active after payment is confirmed.”
Vague “Proceed” without amount or item.
Upgrade prompt “Forum posting is available to active
members. Subscribe to join the discussion.”
Shaming or confusing paywall language.
Payment failed “Payment was not completed. You were not
charged by UNNG. Try again or choose
another option.”
Technical payment errors without next
step.
Delete profile “This will deactivate your account and log
you out. Your previous forum posts may
remain as Deleted User.”
One-tap destructive delete.
Empty events “No upcoming events yet. Check back soon
or explore organizations.”
Blank list.
No transactions “You have no payments yet. Donations,
subscriptions, and event payments will
appear here.”
“No data.”
